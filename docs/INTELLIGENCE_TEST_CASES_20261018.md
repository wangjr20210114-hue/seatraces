# 智能旅行增量测试用例与结果

本轮目标是 6 项功能和 4 项服务。这里只登记已经实施、实际执行的检查，未列功能不代表完成。环境为本机隔离 PostgreSQL 和 Edge；地图/模型使用替身，无正式账号和付费请求。

| 用例 | 模块 | 简单步骤 | 预期 | 结果 |
|---|---|---|---|---|
| INTEL-Q01 | 问答/已知条件 | 输入“明早去上海，两天，带父母，不想走太多，之前去过外滩” | 保留日期/同行人/交通/到访；只补缺失条件 | 通过，规则与规划服务测试 |
| INTEL-Q02 | 问答/分支 | 父母同行、少走路；再改为独自、综合交通 | 前者出现步行上限和结束时间；后者不带入未确认或已失效分支 | 接口及网页通过 |
| INTEL-Q03 | 问答/兴趣 | 历史偏好园林，本次明确选择人文 | 园林只作确认建议；本次人文优先，出现游览深度问题 | 通过 |
| INTEL-Q04 | 问答/不确定性 | 说“如果带父母”“没去过外滩”“不带父母” | 不把假设或否定当成已确认事实 | 通过 |
| INTEL-Q05 | 问答/边界 | 非本人问卷、未知字段、无效时间、无限步行上限、20并发 | 跨用户404；输入400；合法请求有界完成 | 通过 |
| INTEL-Q06 | 规划/约束 | 排除外滩，选择人文深入，13点前结束 | 排除覆盖想去；博物馆规则时长增加；安排不超过结束时间 | 通过；步行量仍标记估算，不假称实测 |
| INTEL-Q07 | AI/确认 | 多条件建行程，完成选项，确认生成 | 取题带当前已确认答案；创建及生成均须确认；不能扩宽白名单 | 既有智能体回归通过 |

新增问答专项共 4 项（包含真实HTTP和20并发），结合既有组合需求与兴趣回归共 13 项通过。网页最终通过 2 项（动态问答和分维度反馈），页面测试前 58 个既有测试文件产生 368 个通过事件、0失败；这些计数有重叠，不相加。

首轮发现工作流白名单拒绝新增确认答案，已修复为严格绑定当前对话答案。旧回归还固定了单次取题调用，现核对动态第二次取题携带确认值；网页测试最初假定固定标题和空兴趣默认值，现明确清空再选，核对真实分支。失败记录保存在 `validation/intelligence/dynamic-before/` 和 `dynamic-second/`；不把它们计为成功。最终截图在 `reports/ui/adaptive-questionnaire.png`。截图底图是测试占位，不能作为真实地图供应商验收。

## 分维度反馈

| 用例 | 模块 | 简单步骤 | 预期 | 结果 |
|---|---|---|---|---|
| INTEL-F01 | 反馈/分开记录 | 整体2分、地点5分、节奏太赶 | 原样保存三种评价，园林兴趣正向，慢节奏成为待确认建议 | 真实HTTP→数据库→画像通过 |
| INTEL-F02 | 反馈/范围 | 只评价餐饮1分，无地点评价 | 不把美食类别或游玩地点记成讨厌；不生成地点满意/不满意训练标签 | 通过 |
| INTEL-F03 | 反馈/临时条件 | 本次带父母 | 行程保留本次事实，反馈不写成永久同行人或类别偏好 | 通过 |
| INTEL-F04 | 反馈/撤销和权限 | 他人尝试改；本人改成餐饮单项评价、再撤销 | 他人404；旧节奏证据消退；撤销后读取为空 | 通过 |
| INTEL-F05 | 网页/独立评分 | 在历史行程选整体2分；地点先为空，改成5分，节奏太赶；保存刷新 | 不自动把2分复制到地点；刷新后各维度一致 | Edge通过 |

反馈专项2项（含隔离HTTP链路）通过。生产需要重新执行 `server/recommendation/schema.sql` 更新既有反馈触发器：明确地点评分独立于节奏/餐饮；有方面评价而缺少地点评分时，不从整体分推断地点标签。没有新表，没有删除旧评价，迁移仍应备份。

```powershell
$env:TEST_FEEDBACK_DIMENSIONS='1'
node --max-old-space-size=320 --test test/feedback-dimensions.test.mjs
node scripts/ui-test.mjs run e2e/specs/feedback-dimensions.spec.mjs --project=desktop
```

首次专项发现单一明确反馈的建议置信度阈值过高，调整为只产生可确认的弱建议；之后测试SQL误用不存在的 created_at 列，修正为自增结果ID顺序，最终通过。没有修改模型激活门槛。网页两个测试在同一轮通过后拆成按模块命名的文件，内容保持一致。
