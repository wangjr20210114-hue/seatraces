# 地点语义召回与高德天气启用验收

日期：2026-10-19（北京时间）。本轮复用正式版本已有接口、服务器已有 BGE 模型和高德凭据；没有新增数据库表、向量索引、第三方密钥、模型下载或线上推荐模型训练。

## 功能与范围

| 模块 | 行为 | 边界 |
| --- | --- | --- |
| 地点名称语义补位 | 打开服务器 `EMBEDDING_ENABLED=true`。字面检索未找到具名地点时，在查询区域内补取候选并用本机 BGE 排序 | 最多60个候选，每批25个地点；先过滤类别、国家和半径。相似度不是实体同一性证明，不自动添加别名 |
| 地点语义失败降级 | 模型不可用、超时或繁忙时保留字面检索和既有外部补充规则 | 不无限排队，不扩大地点范围，不靠模型虚构地点 |
| 行程天气 | 已保存行程的每日视图 → “天气与预警”，复用高德 Web 服务 Key 获取预报 | 只查询本人行程；超过预报范围明确提示；按来源发布时间判断时效 |
| 天气复用 | 同城有效缓存复用，重复查看不再请求供应商 | 有效期最多1小时；源发布超过12小时不能当作当前有效预报 |
| 官方预警 | 本轮保持 `not_configured` | 用户还没有和风账号，不把高德天气建议当作官方灾害预警 |

接口不变：`POST /api/catalog/candidates`、`GET /api/journey/trips/:id/weather?day=0`、`GET /api/journey/trips/:id/weather-alerts?day=0`。

## 服务器执行与证据

`deploy/activate-place-weather.py` 仅允许用于已验收的应用镜像 `seatraces-business:git-c7de59ddaa47`。它核验五个已安装模型文件的 SHA256、天气表及已有高德配置，备份 `backend.env` 后仅设置语义开关，重新创建后端容器。

随后创建两个禁止密码登录、排除运营统计的短期普通验收账号，经真实HTTP检查语义补位、天气、缓存、日期及越权；检查结束清除本批账号和行程。独立到期清理覆盖验收进程意外退出；不删除正式用户。采样真实后端进程RSS，超过560MiB或发生重启则恢复原配置。后台记录 `capabilities.place_weather.activated`，只含安全验收元数据，不含密钥、会话或个人内容。

启用进度附加到已有部署状态文件的 `placeWeatherActivation` 字段，可通过现有只读部署连接查询。没有扩大SSH权限或修改已安装部署网关。

本文件生产结果待实际启用后补记，不能用本机结果替代生产验收。

## 手动验收

1. 登录自己的账号，打开近期行程并选择某一天，点击“天气与预警”。应看到日期对应的天气与温度；远期行程显示“尚未进入预报范围”。官方预警暂未配置的提示保留。
2. 断开浏览器网络后点击天气按钮，应结束加载并显示失败；恢复网络后可再次点击并读到结果。
3. 通过具名地点候选接口，在衢州市中心、半径3公里内搜索“衢州孔庙”，禁止高德补充时应仍能得到“孔氏南宗家庙”，响应中 `local_spatial` 为 `ready`。
4. 后台 → 操作日志，搜索 `capabilities.place_weather.activated`，查看通过结果与资源信息。账号、地点库、已验证邮箱和邮件配置应保留。

接口依据：[高德天气](https://lbs.amap.com/api/webservice/guide/api/weatherinfo)、[和风官方预警](https://dev.qweather.com/en/docs/api/warning/weather-alert/)。
