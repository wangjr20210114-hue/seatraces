# 双塔正文语义与近期兴趣离线实验

## 结论

已按用户授权增加本机语义缓存，并完成四组 CPU 对照。**本轮配置未超过原基线，未激活或上传实验模型。** 增加语义输入与多层投影没有在现有模拟标签上带来稳定收益。不能把这个结果解释为语义推荐对真实用户必然无效。

本次仅新增离线脚本、测试和文档，不改 HTTP 接口、数据库结构、线上排序或既有 BGE 名称检索接口。

## 数据与方法

- 同一份现有成熟模拟曝光：4,500 对，训练 2,498、验证 666、历史测试 900；时间分区之间保留完整七天标签窗口。
- 数据摘要：`bbaf06015f61c6348408208f7db9412686f3d90f3a55f80e1100617ed032c6dc`，与上一轮容量实验一致。没有新造行为或改标签。
- 440 篇被曝光的模拟帖子，读取标题、正文和标签；10 种显式偏好文本，共编码 450 条。正文没有加入作者 ID 或用户 ID。
- 使用本机固定版本 `Xenova/bge-small-zh-v1.5`，revision `75c43b069aac4d136ba6bc1122f995fedcfd2781`、q8、CLS pooling、512 维归一化输出、最多 256 token，逐条 CPU 编码，不联网。
- 短偏好文本使用 BGE 的中文检索指令，帖子正文不加指令，依据 [BGE 官方模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)。文本长度上限会截断较长正文，这是本轮的限制。
- 缓存键包含文本摘要、模型版本、量化方式、pooling 和长度配置。缓存文件只含键与向量，不保存原文；输入改变会换键，维度、数值或归一化校验失败时重新计算。
- 近期兴趣使用当前曝光之前已结束完整七天观察窗口的正反馈，最近 30 天最多 20 条，按权重及七天半衰期聚合。融合比例预先固定为显式偏好语义 0.6、历史语义 0.4；没有用验证或测试成绩搜索该比例。
- 断言当前帖子 revision 为 1，且内容更新时间、发布时间均不晚于历史曝光；缺少可信历史正文时直接停止，不拿修改后的正文回填历史特征。
- 两层用户塔和帖子塔独立训练，tanh、输出 L2 归一化，温度固定为 4，以加权二分类交叉熵训练。加入语义时每塔输入 608 维：原 96 维结构化块与 512 维语义块等权归一化；输出 32 维。
- 配置在训练前写入报告；每六轮检查验证集，最多 36 轮。仅用验证集选模型/轮次，选定后只评价该模型的历史测试集。

## 结果

| 配置 | 参数量 | 验证选择轮次 | 验证 NDCG@10 | 训练时间 |
|---|---:|---:|---:|---:|
| 原余弦基线 | — | — | **0.7962** | — |
| 结构化输入，两层 32 宽 | 8,321 | 24 | 0.7649 | 7.32 秒 |
| 结构化＋正文语义，两层 32 宽 | 41,089 | 18 | 0.7356 | 29.07 秒 |
| 再加近期兴趣，两层 32 宽 | 41,089 | 30 | 0.7344 | 28.76 秒 |
| 再加近期兴趣，两层 64 宽 | 82,113 | 30 | 0.7479 | 55.13 秒 |

不训练、直接用 BGE 相似度排序的验证 NDCG 分别为静态偏好 **0.6495**、加入近期兴趣 **0.6125**。语义分数的表达能力和它与本批标签的匹配程度是不同问题。

验证选择的是结构化输入的两层模型。其历史测试 NDCG **0.7924**，原基线 **0.8074**；差值 **-0.0150**，按用户配对抽样的诊断性 95% 区间 **[-0.04459, +0.01532]**。未达到原有上线门槛。

语义输入确实增加了区分度：440 篇帖子得到 440 种不同向量；50 个用户都有历史可用，3,986 条曝光使用了成熟历史，单条最多用到 10 条。这些计数不代表推荐效果提升。

本轮总耗时 **144.02 秒**，进程峰值 RSS **399 MiB**，结束时 JS 堆 **145 MiB**，设置 `--max-old-space-size=320`。450 份本机缓存共 **4,893,589 字节**，约 4.9 MB。RSS 包含 ONNX 原生内存，不能只按 JS 堆估算；该测量来自独立离线进程，不是线上 HTTP 服务容量。暂不需要显卡。

## 验证与保护

与前一轮实验测试一起共 **9 项通过、0 失败、0 跳过**：

- 两个塔的两层权重及偏置梯度均与有限差分一致。
- 简单偏好样本能学到正确区分，训练不修改输入，非法容量和标签被拒绝。
- 当前标签、未成熟标签及未来反馈不能改变当前曝光的语义历史。
- 缓存复用、正文变化、损坏向量与非法编码输出均覆盖。
- CLI 拒绝 `--real` 和 `--activate`；仅接受 `--local`，本地 DB helper 还拒绝 production 环境。
- 实验模型标识为 `offline-semantic-mlp/1`，线上加载器不接受该模型。

第一次在 Windows 沙箱执行时，临时缓存重命名被环境以 EPERM 拒绝；使用正常本机文件权限后全部测试通过。没有为测试放宽模型校验。

## 如何复现

先启动现有本机 PostgreSQL，并保留已经准备的 BGE 文件：

```powershell
node --test test/tower-semantic.test.mjs test/tower-experiment.test.mjs
node --max-old-space-size=320 scripts/experiment-semantic-recommendation.mjs --local
```

上限为 5,000 条样本、1,000 篇帖子；超过时停止，不静默截断。脚本只读本机模拟数据；模型、缓存和报告位于被 Git 忽略的 `validation/tower-semantic/`。缓存可复用，但重复运行仍会重新训练四组配置。

## 后续判断

1. 现有模拟正反馈主要由结构化余弦相似度产生，正文里额外的语义并未独立决定反馈。因此应先补充独立的人工偏好评估和成熟真实互动，再判断哪种表示更适合产品。
2. 真实用户对模拟帖子的反馈需保留来源组合，不能混作纯真实内容效果；也不能把模拟标签改成恰好偏向 BGE 来宣称提升。
3. 历史测试集已被旧版本评估过，只能用于诊断。正式模型仍需新的时间窗口，以及按请求计算的召回、排序、收藏、采用路线与满意度指标。
4. 不将这批失败实验部署到发现页。其余个性化功能的正式发布仍以 `89d369f` 的服务器验收结果为准，离线实验完成不等于正式发布完成。
