# 旅行内容推荐：多模型离线对照

日期：2026-10-18。此次新增四个方向的实际 CPU 实验，均已完成。没有修改线上排序、数据库结构、服务器配置或模型启用门槛。更大的个性化目标仍未完成：当前没有达到启用条件的双塔模型。

## 试了什么

| 方向 | 实际运行的版本 | 适合研究的作用 | 权重来源 |
|---|---|---|---|
| 中文 BGE-base | 768 维、CLS 池化、q8、最大 256 token | 中文帖子语义检索、冷启动候选 | [BAAI 原模型](https://huggingface.co/BAAI/bge-base-zh-v1.5)的 [Xenova ONNX 转换](https://huggingface.co/Xenova/bge-base-zh-v1.5)，下载了现成权重 |
| multilingual E5-small | 384 维、mean 池化、q8、最大 256 token | 中文及多语言帖子语义检索 | [intfloat 原模型](https://huggingface.co/intfloat/multilingual-e5-small)的 [Xenova ONNX 转换](https://huggingface.co/Xenova/multilingual-e5-small)，下载了现成权重 |
| DIN 适配版 | 100,738 个可训练参数，64 维投影 | 针对当前候选，从成熟历史互动中选取相关兴趣 | 根据 [DIN 论文](https://arxiv.org/abs/1706.06978)实现候选条件注意力，使用已缓存的 BGE-small 内容特征；排序层从零训练 |
| DCN-V2 适配版 | 142,145 个可训练参数，2 层矩阵交叉、并行 MLP | 用户偏好、帖子内容和历史兴趣的特征组合 | 根据 [DCN-V2 论文](https://arxiv.org/abs/2008.13535)实现矩阵交叉层；排序层从零训练 |

DIN 使用 softmax 注意力与小型 MLP，没有复刻原工业系统的全部技巧；DCN-V2 使用矩阵交叉形式，没有使用混合专家版本。它们是论文结构的项目适配实验，不是下载来的旅行推荐成品，也不是原论文完整复现。语义编码器本身并不等于经过用户行为训练的双塔推荐系统。

前一轮真实加载的 UniSRec 预训练模型也列入参考；它的来源、适配桥、参数和实验见 [UniSRec 诊断](TOWER_DIAGNOSIS_20261018.md)。本轮没有重新训练或改写其结果。

## 数据与实验约束

- 复用已冻结的 4,500 条成熟模拟曝光、440 篇帖子、10 种显式画像；不是 4,500 名用户。
- 训练 2,498 条、验证 666 条、历史测试 900 条；另有 436 条处于隔离时间段，不参与训练或指标计算。
- 完整七天标签窗口；历史内容仅取当时已完成观察窗口的正向互动，最多 20 条、近 30 天。当前答案和未来反馈不能进入输入。
- 每篇文本必须来自同一模拟帖子 ID 和 revision 1，创建、修改时间早于曝光；导出为只读事务，并与上一轮数据、语料摘要核对。没有读取正式用户对话或生产数据库。
- DIN/DCN-V2 各使用固定三个随机种子、12 个 epoch、batch 32、AdamW 学习率 0.0003、两个 CPU 线程、加权 BCE。每 3 个 epoch 查看验证分数，按验证选择各个种子的 epoch；报告全部种子，不按测试分数挑选。
- 两个预训练编码器各编码 440 篇帖子和 10 种画像。按模型卡使用查询前缀和池化方式；E5 对中文同样使用 `query: `、`passage: `。另预先规定一个“显式偏好 0.6＋历史语义 0.4”的对照，不根据测试结果改比例。
- 历史测试已经被多轮实验查看，且标签生成偏向规则余弦分数；本轮是诊断比较，不是新的独立测试，也没有据此降低上线门槛。指标按用户汇总历史候选，不等于真实每次刷新请求的线上指标。

## 排序结果

NDCG@10 越高表示前十项更接近该数据集的标签顺序，不是准确率。

| 方法 | 验证 NDCG@10 | 历史测试 NDCG@10 | 说明 |
|---|---:|---:|---|
| 原规则基线 | **0.7962** | **0.8074** | 模拟标签生成方式对该基线有利 |
| UniSRec 预训练适配（上一轮） | 0.7561 | 0.7784 | 验证选择的冻结版本 |
| BGE-base 纯语义 | 0.6510 | 0.6440 | 无用户反馈训练 |
| BGE-base＋历史语义 | 0.6266 | 0.6018 | 固定 0.6 / 0.4 对照 |
| E5-small 纯语义 | 0.6492 | 0.6542 | 无用户反馈训练 |
| E5-small＋历史语义 | 0.6246 | 0.6104 | 固定 0.6 / 0.4 对照 |
| DIN 适配版 | 0.6655 ± 0.0079 | 0.6946 ± 0.0104 | 三种子平均 ± 样本标准差 |
| DCN-V2 适配版 | 0.6254 ± 0.0049 | 0.6632 ± 0.0079 | 三种子平均 ± 样本标准差 |

新训练的六个版本均未超过基线。各版本的历史测试差值按用户配对 bootstrap 的 95% 诊断区间均低于 0；两个纯语义模型也如此。无成熟历史组只有验证 15 条、测试 31 条，含正样本的用户组分别仅 2 和 3 个，不能据此声称冷启动有效。

这说明当前输入、训练预算及模拟标签下，没有理由替换线上规则；不能扩大为“DIN、DCN-V2 或 E5 在真实旅游推荐上无效”。相同文字主题、语义相关和用户愿意收藏或采用路线是不同目标。

## 本机成本

| 实验 | 实测计算时间 | 峰值进程 RSS | 其他观测 |
|---|---:|---:|---|
| BGE-base 编码＋评估 | 112.84 秒 | 463.44 MiB | 单篇编码 P50 239.7 ms、P95 355.4 ms |
| E5-small 编码＋评估 | 38.42 秒 | 768.46 MiB | 单篇编码 P50 71.0 ms、P95 117.5 ms |
| DIN / DCN-V2 共六次训练＋评估 | 79.16 秒 | 259.97 MiB | 900 条已缓存特征评分约 94～250 ms，视模型而定 |

合计计算约 3 分 50 秒，不包括下载、开发和人工检查。均为 CPU，当前实验不需要显卡。单篇编码和离线批量评分均不是 HTTP 延迟，也不能外推生产并发容量。RSS 包含框架、模型初始化、原生库和文件处理，不能只看 JS 堆。

本轮模型、向量、结果和小型排序器权重共约 241 MiB，位于被 Git 忽略的 `validation/travel-models/`；此前独立 PyTorch 环境及 UniSRec 文件另计。BGE-base 模型文件合计 103,309,299 字节，E5 合计 135,392,183 字节。

当前正式后端容器上限 640 MiB，E5 本次独立进程峰值已超过它，不能直接放进现有后端。BGE-base 虽较低，也没有完成“业务进程＋模型＋并发”的服务器容量验收。若以后采用，优先评估离线编码帖子、在线只读向量；任何额外缓存、查询、数据结构或部署优化仍按既有约定另行确认。

## 结论与下一步

1. 保留当前规则排序与质量门槛，本轮四个方向都不启用到生产。
2. E5 可作为下一轮候选检索对照，DIN 可作为有足够真实历史后的精排对照；两者所处阶段不同，不能当成互斥的替代品。目前没有足够证据指定它们为赢家。
3. 先增加独立评审者和未见题目、积累自然真实互动。只有十种模拟画像，继续增加参数并不能补齐真实偏好信息。
4. 后续把候选检索覆盖、最终排序和用户采用/满意度分开评估；不要只优化这批已反复查看的 NDCG。

## 已授权的轻量精排补充实验（同日后续）

用户随后批准加入 LightGBM、保留请求分组和分项行为、准备新盲评。此次只读导出及 9 次 CPU 训练均已完成，没有修改生产排序、真实数据或双塔启用门槛。

### 请求与标签审计

实际本机统计：4,500 次模拟请求、4,500 次曝光，每个请求恰好一篇候选、一次曝光，多候选请求数为 0。原生成器每次创建单候选请求，这不是导出丢失。不能通过这些请求测得有意义的单次推荐排序指标；本轮按 requestId 计算时明确返回无结果，不把单候选的完美分数当作成绩。

因此，本轮 LightGBM 明确使用“同一时间分区内，按用户汇总历史曝光”的诊断组，与旧 NDCG 口径对齐；没有把它称为真实推荐列表。请求 ID、展示位置、可见时长及分项行为仍保留用于审计，不作为模型输入。数据库没有记录候选选择概率，未声称进行了逆倾向加权去偏。

原二分类标签、权重、用户/帖子配对、时间划分与冻结源逐项核对未变。新增的次要分级标签只用于独立对照：负反馈或无正反馈 0，点赞/评论/关注 1，收藏/推荐 2，采用 3，满意 4；负反馈覆盖正反馈，不重复相加。训练和评价使用线性等级增益。这个约定属于离线试验，不将评论一概解释为赞同，也不改变线上画像权重。

### 实际训练

- 隔离 Python 环境新增 LightGBM 4.6.0、SciPy 1.15.3；保留 NumPy 2.2.6。固定依赖位于 `scripts/requirements-ranking-cpu.txt`，`pip check` 通过。默认 pip 镜像和官方 pip 连接均失败后，从官方 PyPI wheel 地址下载，逐一核对其元数据 SHA-256，再离线安装；未关闭 TLS 验证。
- 每组固定 3 个种子（20261018～20261020）、100 轮、2 个 CPU 线程；7 个叶节点、深度 3、学习率 0.03、L2=5，每 10 轮只看验证集。保留第 0 轮原规则候选；没有收益时可选择不加模型修正。
- 从**现有完整精排规则的 margin** 开始，用 LambdaRank 学习修正量。保存模型后重新加载验证“原规则分数＋模型修正量”一致；LightGBM 模型文件本身不保存 init_score，不能直接只用文件预测替换最终分数。
- `binary-rules` 有 8 个输入：原规则 margin、兴趣相似度、粗排分、作者、时效、质量、城市、已看状态。当前模拟样本中的常量特征仍如实保留。
- `binary-rich` / `graded-rich` 有 205 个输入，在上述基础上增加 BGE-small 语义匹配、成熟历史匹配/数量/缺失标志，以及 96 维结构化特征的乘积和差值。当前样本的标签、行为、可见时长、展示位置和身份 ID 不进入特征。历史仍要求完整七天窗口结束。

### 完整结果

下表仍使用旧**二分类 NDCG@10**，三种子平均。分级训练组的 checkpoint 按分级验证目标选择，其二分类值仅作共同诊断，未拿不同指标相互比较。

| 方法 | 验证 | 历史测试 |
|---|---:|---:|
| 旧余弦基线 | 0.7962 | 0.8074 |
| 现有完整精排规则 | 0.7887 | 0.8220 |
| 规则＋轻量精排 binary-rules | **0.8083** | **0.8265** |
| 增加语义和交叉特征 binary-rich | 0.8051 | 0.8093 |
| 分级训练 graded-rich | 0.8057 | 0.8047 |

各次运行均保留，未挑选测试分数最高的种子对外报告：

| 组别 | 种子末两位 | 验证选中轮次 | 二分类验证 / 测试 | 分级测试 |
|---|---:|---:|---:|---:|
| binary-rules | 18 | 30 | 0.8059 / 0.8240 | 0.7671 |

| binary-rules | 20 | 100 | 0.8086 / 0.8271 | 0.7751 |
| binary-rich | 18 | 30 | 0.8059 / 0.8044 | 0.7440 |
| binary-rich | 19 | 80 | 0.8019 / 0.8101 | 0.7494 |

分级测试基线分别是余弦 0.7436、完整规则 0.7644；不能拿分级模型的新分数同旧二分类 0.8074 直接比较。

仅按验证集选定的二分类候选为 `binary-rules / 20261019 / 100`，历史测试 0.8284。与余弦差值为 +0.0210，按用户配对 bootstrap 的诊断 95% 区间 [0.0014, 0.0442]；与实际完整规则差值只有 +0.0064，区间 [-0.0108, 0.0242] 仍包含零。另外两个种子相对完整规则的区间也包含零。这支持继续独立评价，不证明真实用户收益、双塔达标或应上线。该历史集已经反复用于诊断，区间不是新的独立确认性检验。

结果提示当前数据下额外语义特征没有带来收益；不能据此断言真实旅行偏好不需要语义。先保留简单候选做新盲评，不继续按旧测试集挑特征或调参数。
