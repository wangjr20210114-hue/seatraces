## 功能边界

1. 兴趣证据经既有 profile / travelHabit 影响新问卷、候选景点评分和行程筛选。本轮修正了问卷选项只按标签插入顺序排列的问题；明确偏好优先，再按推断兴趣强度排列。已有问卷不擅自修改答案。
2. 顶层景点先按 personalInterest 再按原总分显示。父景点可承接少量最高子景点兴趣，避免子景点数量多就无限加分。最终安排仍先满足本次“想去”、开闭园、时间预算及地理约束，不保证所有高兴趣地点都能排进。
3. 发现滚动到底追加：先读当前冻结推荐池，耗尽后以已显示 ID 请求下一池。每5个位置保留一个探索位；去重、并发合并、过期恢复、失败保留卡片。每轮最多600张，避免页面无限增长。
4. 收藏/浏览复用图文卡片，显示作者、封面、城市、发布时间与收藏/最近浏览时间。浏览天数是不同日期的记录数，不是访问次数。
5. 顶层景点简介可悬浮或键盘聚焦展开。只为可见卡片按需请求；PostgreSQL 地点扩展表缓存，完整资料不进入问卷。仅名称/类别时保留基础介绍；模型只摘录已有证据，不编百科知识。
6. 问 AI 使用既有内部接口工作流与授权校验。RAG 已实际使用本机 BGE 512维向量，并修正知识文档和排序；无模型文件时接口明确返回 lexical，不能称为向量检索。

## 双塔诊断

详见 [训练诊断](TOWER_DIAGNOSIS_20261018.md)。完成7组 CPU 实验，最大参数24,577，为原来的4倍；全程82.69秒，峰值143 MiB。

模拟行为由余弦兴趣规则生成，所以余弦基线接近已知数据生成器。扩大模型后历史测试 NDCG@10 从0.8021提高到0.8080，基线0.8074，但验证集仍落后，差值置信区间包含0。实验模型未激活；保留原有上线质量门槛。该结果不能证明真实用户推荐质量提高，也不需要为此购买GPU。

本机成熟真实训练样本为0，不等于线上没有行为。训练器当前还按用户和内容两端的模拟标记区分数据范围，真实用户阅读模拟帖子不属于纯真实训练集。后续应单独评估这种混合数据，不能去掉标记冒充真实数据。

耗时取单次本机测量；真实模型测试与 UI 外部供应商替身分开报告，不外推成生产容量。BGE RSS包含原生 ONNX 内存，不能只看JS堆大小。生产目前的640MiB容器仍需上线后做并发观测；本轮没有额外增加容器资源或调整索引。

网页验收进程（后端+测试托管程序，排除浏览器/PostgreSQL/子测试进程）峰值RSS104 MiB、JS堆36 MiB，1秒间隔采样、使用小型合成地点集。不能与独立BGE进程的峰值简单相加作为生产实测值。

网页验收实际发现并修复了“想去”按钮状态错误：后端已保存，前端却访问已删除的 `.cluster-hint` 元素而中断后续更新。现在移除旧元素依赖，并按服务端确认的 wanted 值更新按钮。用例同时覆盖添加与取消，不仅检查HTTP 200。

地图封面及外部地图瓦片在隔离网页测试中不联网，截图里的占位区不能当成真实高德地图验收结果。此前一次浏览器测试因本机缺少Playwright默认浏览器无法启动，随后改用已安装Edge完成测试；该环境失败不计作功能通过。

## 复现

先启动本机 PostgreSQL（`npm run dev`）。下面命令使用隔离测试 schema；不使用生产账号。

```powershell
$env:TEST_PERSONAL='1'
$env:TEST_RECOMMENDATION='1'
$env:TEST_AGENT='1'
node --max-old-space-size=320 --test --test-concurrency=1 test/*.test.mjs
$env:TEST_RAG_LIVE='1'
node --max-old-space-size=320 --test test/agent-rag-live.test.mjs
node scripts/ui-test.mjs run e2e/specs/personalization.spec.mjs e2e/specs/agent.spec.mjs --project=desktop
```

UI测试使用19888/19887和一次性PostgreSQL，地图/外部路线请求使用替身，不触碰线上用户；CLI自动选择已安装浏览器。报告在忽略Git的 `reports/ui/`。生产部署前须备份并迁移 `server/place-descriptions-schema.sql`；向量模式还需要服务器实际装有固定版本BGE模型。
