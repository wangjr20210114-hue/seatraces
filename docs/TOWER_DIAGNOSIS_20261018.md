# 双塔训练诊断与容量对照（2026-10-18）

## 结论

本轮继续使用 CPU 训练，不需要显卡。将参数扩大四倍并增加轮数，尚未得到可稳定超过规则基线的模型。未激活实验模型，未修改模拟标签、生产数据或线上模型。

现有推荐功能仍可由兴趣召回、协同召回、粗排、细排和多样性重排工作；“有个性化推荐”和“已启用通过验收的双塔”是两件事。

## 为什么落后

1. **模拟标签偏向基线。** `server/recommendation/demo.mjs` 的正反馈概率为 `min(0.9, 0.07 + max(0, cosine(user, item)) * 0.95)`。余弦相似度同时就是比较基线，因此它掌握了模拟偏好的生成规则。双塔学习的是同一规则加随机噪声，不能把超过它当成天然应达到的结果。
2. **延长训练出现过拟合迹象。** 32 维模型训练损失从 0.7394 降到 0.5285，但验证 NDCG 在第 12 轮达到 0.7679，至第 72 轮降为 0.7633。训练损失下降不等于推荐排序变好。
3. **目标与指标不同。** 原训练优化加权二分类交叉熵，验收关注 Top-10 排序。本轮分别试了均衡二分类和同用户正负样本成对排序；均未稳定超过基线。
4. **数据量与信号有限。** 共 4,500 对成熟模拟曝光，实际训练只有 2,498 对、50 个模拟用户；本机真实数据按现有成熟条件提取为 0，这不代表线上没有行为。模型容量变大不能替代真实偏好、负反馈和跨时间数据。

## 实验方法

- 使用现有数据，标签与种子不变；没有新造行为来让模型过关。
- 按时间分区，并在训练/验证及验证/测试之间留完整 7 天反馈窗口。
- 训练 2,498 对，验证 666 对，历史留出测试 900 对。
- 预先固定 7 组配置，只根据验证集选择轮数和模型；随后只报告选定模型的历史留出测试结果。
- 该留出集在之前的版本已评估过，属于历史诊断集，不能称为新获得的真实用户证据。
- 实验文件使用单独算法标识，线上加载器拒绝它们。实验 CLI 只读本机数据库。

## 复现与保护

```powershell
node --test test/tower-experiment.test.mjs
node --max-old-space-size=320 scripts/experiment-recommendation.mjs --local
```

先启动现有本地 PostgreSQL。结果保存在忽略提交的 `validation/tower-diagnosis/`，包括数据摘要哈希、每个验证检查点和选定模型。实验脚本不会写入数据库模型表，也不会改变激活状态。

4 项实验回归通过：与原 SGD 权重完全一致、较大/成对模型确实学习、时间隔离与非法输入拒绝、按用户统计的不确定区间。不要把“扩大模型”“增加训练轮数”本身作为上线理由。后续需要持续积累成熟真实曝光与反馈，在新的时间窗口上验证；模拟内容及真实用户与模拟内容的互动应明确记录其来源，不冒充纯真实内容评估。
