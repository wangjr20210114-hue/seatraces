# 双塔训练诊断与容量对照（2026-10-18）

## 结论

本轮继续使用 CPU 训练，不需要显卡。将参数扩大四倍并增加轮数，尚未得到可稳定超过规则基线的模型。未激活实验模型，未修改模拟标签、生产数据或线上模型。

现有推荐功能仍可由兴趣召回、协同召回、粗排、细排和多样性重排工作；“有个性化推荐”和“已启用通过验收的双塔”是两件事。

## 为什么落后

1. **模拟标签偏向基线。** `server/recommendation/demo.mjs` 的正反馈概率为 `min(0.9, 0.07 + max(0, cosine(user, item)) * 0.95)`。余弦相似度同时就是比较基线，因此它掌握了模拟偏好的生成规则。双塔学习的是同一规则加随机噪声，不能把超过它当成天然应达到的结果。
2. **延长训练出现过拟合迹象。** 32 维模型训练损失从 0.7394 降到 0.5285，但验证 NDCG 在第 12 轮达到 0.7679，至第 72 轮降为 0.7633。训练损失下降不等于推荐排序变好。
3. **目标与指标不同。** 原训练优化加权二分类交叉熵，验收关注 Top-10 排序。本轮分别试了均衡二分类和同用户正负样本成对排序；均未稳定超过基线。
4. **数据量与信号有限。** 共 4,500 对成熟模拟曝光，实际训练只有 2,498 对、50 个模拟用户；本机真实数据按现有成熟条件提取为 0，这不代表线上没有行为。模型容量变大不能替代真实偏好、负反馈和跨时间数据。

## 实验方法

- 使用现有数据，标签与种子不变；没有新造行为来让模型过关。
- 按时间分区，并在训练/验证及验证/测试之间留完整 7 天反馈窗口。
- 训练 2,498 对，验证 666 对，历史留出测试 900 对。
- 预先固定 7 组配置，只根据验证集选择轮数和模型；随后只报告选定模型的历史留出测试结果。
- 该留出集在之前的版本已评估过，属于历史诊断集，不能称为新获得的真实用户证据。
- 实验文件使用单独算法标识，线上加载器拒绝它们。实验 CLI 只读本机数据库。

## 结果

| 原双塔 | 6,145 | 18 | 12 | 0.7679 | 2.35 秒 |
| 增加轮数 | 6,145 | 72 | 12 | 0.7679 | 9.05 秒 |
| 两倍参数 | 12,289 | 72 | 36 | 0.7703 | 19.82 秒 |

| 成对排序 | 6,145 | 40 | 40 | 0.7652 | 1.71 秒 |
| 成对排序、两倍参数 | 12,289 | 40 | 40 | 0.7702 | 3.58 秒 |
| 余弦基线 | — | — | — | **0.7962** | — |

验证选中的四倍参数模型在历史留出测试上 NDCG 为 **0.8080**，基线为 **0.8074**，差值只有 **+0.00063**。按用户配对自助抽样的诊断性 95% 区间为 **[-0.01968, +0.02192]**，包含零；验证集仍落后，未达到原有双重验收门槛。

整轮耗时 **82.69 秒**，峰值 RSS **143 MiB**，使用 `--max-old-space-size=320`。这是离线单进程训练测量，不等于生产 HTTP 服务的容量。

## 复现与保护

```powershell
node --test test/tower-experiment.test.mjs
node --max-old-space-size=320 scripts/experiment-recommendation.mjs --local
```

先启动现有本地 PostgreSQL。结果保存在忽略提交的 `validation/tower-diagnosis/`，包括数据摘要哈希、每个验证检查点和选定模型。实验脚本不会写入数据库模型表，也不会改变激活状态。

4 项实验回归通过：与原 SGD 权重完全一致、较大/成对模型确实学习、时间隔离与非法输入拒绝、按用户统计的不确定区间。不要把“扩大模型”“增加训练轮数”本身作为上线理由。后续需要持续积累成熟真实曝光与反馈，在新的时间窗口上验证；模拟内容及真实用户与模拟内容的互动应明确记录其来源，不冒充纯真实内容评估。

## 语料审计补记

加入只读本机审计 `scripts/audit-recommendation-corpus.mjs`，用于区分生成规则的问题与模型质量。它不修改帖子、标签、行为、盲评题目或线上模型。

| 检查项 | 2026-10-18 本机结果 | 含义 |
|---|---:|---|
| 模拟帖子 | 500 | 包含 378 篇带路线、122 篇无路线卡帖子 |
| 不同路线快照 | 46 | 按有序地点 ID、名称、分类去重；不是说正文只有 46 种 |
| 不同标签组合 | 9 | 不是独立兴趣维度或真实用户数 |
| 路线地点出现次数 | 1,310 | 同地点在不同帖子中重复出现；不当作唯一地点数 |
| 带 traits 的路线地点 | 0 | 当前模拟快照没有提供这类细粒度属性 |
| 可以重放匹配的帖子 | 500 | 标题、标签、路线和正文均比对；仅忽略正文开头的月日 |
| 截取后丢失主题选路关键词 | 85 / 378（22.5%） | 先按整条路线匹配主题，再取开头若干地点；匹配点可能在被截掉的部分 |

具体例子：艺术主题先选中包含“上海话剧艺术中心”的路线，但截取后只保留武康大楼、黄兴旧居、武康庭等前段地点。可确认的是**主题选路条件没有被保留到最终路线中**，不能据此断言这些地点在现实中完全没有艺术价值。

审计也检查已有名称、类别和 traits 规则能否支持帖子标签。规则未识别到支持，不等于标签错误：例如“安静”“亲子”不能单靠名称判断，“孔庙”未命中当前关键词也不代表无人文价值。工具不自动清洗这些标签。

生成重放依据本次源码与经典路线文件，报告记录它们的 SHA-256；当前库没有独立保存当时被省略的路线尾段，不能把重放称作完整历史还原。报告中的帖子摘要与源文件摘要可用于后续判断数据是否改变。

```powershell
node --max-old-space-size=320 --test test/recommendation-corpus-audit.test.mjs
node --max-old-space-size=320 scripts/audit-recommendation-corpus.mjs --local
```

脚本强制只读事务，只查本机模拟数据；超过 1,000 篇时停止，不静默截断。报告保存在忽略 Git 的 `validation/preference-review/corpus-audit.json`。五项回归覆盖非自动判错、traits 证据、重放归因、正文修改识别、重复/超量输入以及生产参数拒绝。实际读取耗时和峰值内存保存在每次报告中。

这些结果意味着：当前数据适合回归工程链路、诊断表征差异，但不能仅凭增大模型后的模拟成绩宣布真实推荐变好。已经收集的盲评继续按“多篇都可接受”解释；用于诊断后，不再把同一题集当成独立上线测试集。

## 预训练模型兼容性核查

2026-10-18 核对了公开权重说明及实现，尚未下载或启用新模型。

- [UniSRec 官方仓库](https://github.com/RUCAIBox/UniSRec)提供预训练 checkpoint。其[输入生成代码](https://github.com/RUCAIBox/UniSRec/blob/master/dataset/preprocessing/process_amazon.py)默认使用 `bert-base-uncased` 的 CLS 表示；[配置](https://github.com/RUCAIBox/UniSRec/blob/master/props/UniSRec.yaml)为 768 维输入、300 维隐藏表示、2 层序列编码器。我们已有中文 BGE 输出 512 维，补零到 768 维不能解决语义空间不一致。借鉴架构和复用实际预训练权重必须分别报告。
- 其[微调代码](https://github.com/RUCAIBox/UniSRec/blob/master/finetune.py)可以冻结位置与序列编码器，仅适配其余参数。后续若实验，需要记录哪些参数真正从 checkpoint 加载、哪些重新初始化，保留冷启动与有行为历史两组评估。官方数据默认 leave-one-out 划分不替代本项目的时间隔离和成熟反馈窗口。
- [OpenOneRec](https://github.com/Kuaishou-OneRec/OpenOneRec)公开 1.7B/8B 推荐基础模型，采用内容语义 ID 和生成式推荐。它可以作为独立离线对照，但不能把它接入后声称原双塔已达标。它的模型体量不适合直接放进现有 640 MiB 后端容器；尚未做本机资源实测。
- 当前本机 Python 可发现 PyTorch，但未发现 Transformers、RecBole、Safetensors；这里只检查包是否存在，尚未证明它们的版本兼容或推理可用。没有安装新依赖、扩容服务器或修改激活门槛。

下一轮需要分别解决输入适配、语料质量和独立评估数据，不通过更改模拟偏好生成公式使某个模型获得有利标签。正式上线仍以成熟反馈与预先确定的质量门槛为准。
