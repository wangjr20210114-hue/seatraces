# 推荐偏好盲评与真实互动采集

## 这轮要回答什么

既有模拟行为标签由规则兴趣相似度生成，对规则基线有明显偏向。扩大双塔和加入语义特征尚未带来稳定收益。本轮先收集独立人工判断，诊断“规则、已冻结的结构化双塔、BGE语义匹配”在哪些内容上与人的判断不同，不自动训练或激活模型。

使用现有本机模拟内容，包含 10 种旅行偏好、440 篇已编码帖子。确定性挑选 20 组算法相对排序相反的帖子，另加 4 道一致性检查题。评审者看不到模型名称、分数、作者和点赞量；主问题和左右位置在每位评审者的浏览器内随机排列，重复题放在后面。没有标准答案。

题集 ID：`c9f2c99241e7ba03a676949419102bd65413054a34694ddd467c0c4bc7986aaf`。

## 给评审者的操作步骤

1. 本机访问 `http://127.0.0.1:8796/`，点击“开始 / 继续”。
2. 阅读黄色卡片给定的旅行偏好，再比较两篇帖子。按该场景作答，不用猜算法，也不以自己是否住在该城市为标准。
3. 五选一：第一篇、第二篇、两篇都合适、两篇都不合适、信息不足。未给出的预算、开放时间、实际路况不自行假设。
4. 点击“下一题”；可以返回修改，刷新后可继续。共 24 题，预计约 10～15 分钟。
5. 完成后点击“保存到本机实验目录”。若直接双击 HTML 打开，则点击“下载答案文件”，把 JSON 文件交回负责人。

给队友只发送 `validation/preference-review/SeaTraces-推荐盲评.html`。这是自包含的 HTML，不需要登录、网络或本机数据库；可在自己的电脑双击打开。`127.0.0.1` 只指各自电脑，队友不能通过该地址访问你的本机服务。

每人使用自己的浏览器独立完成，全部交卷前不要讨论哪一篇“应该被选”。同一浏览器默认恢复同一人的进度；重做不是一名新评审者。请勿发送私有的算法映射文件或中途公布分数。

## 本机运行与答案收集

在项目根目录执行：

```sh
# 首次准备：仅读本机模拟库和已批准的语义缓存，不调用外部模型
node scripts/prepare-preference-review.mjs --local

# 已生成的题集不要重新生成，直接启动页面即可
node scripts/serve-preference-review.mjs --local

# 导入队友下载的答案；路径含空格时加引号
node scripts/import-preference-review.mjs --local "path/to/seatraces-review-xxx.json"

# 隔离测试，不连接生产库
node --test test/preference-review.test.mjs
```

生成器拒绝覆盖已冻结题集。服务仅绑定 `127.0.0.1:8796`，不需要启动主应用，不连接生产数据库，不开放局域网访问。停止时在运行窗口按 Ctrl+C。

本机文件均在忽略 Git 的 `validation/preference-review/`：

| 文件 | 用途 | 是否发给评审者 |
|---|---|---|
| `SeaTraces-推荐盲评.html` | 自包含题目和作答页面 | 是 |
| `study.json` | 已冻结的公开题集 | 通常只需发 HTML |
| `protocol-private.json` | 模型、语料摘要和题目映射 | 否 |
| `answers/*.json` | 匿名评审 ID、选项顺序、答案、用时 | 仅负责人收集 |
| `answers/*.summary.json` | 单人诊断汇总，不用于模型启用 | 全部交卷后再分析 |

重复提交相同答案不重复写文件；修改后保留版本。分析时按 `reviewerId` 去重，先确定每人最终版本，不能把文件数量当作人数。浏览器只发规范化答案，不上传账号、密码、真实用户画像或浏览记录。HTTP 接口限制同源 JSON、校验 Host、拒绝任意路径，限制请求体 64 KiB。静态站点不提供私有映射、答案或统计文件。

## 如何解释结果

- 按比较组分别报告规则/双塔或规则/语义的被选次数，“都合适”“都不合适”“信息不足”独立列出，不强行折算输赢。
- 重复题仅检查同一人判断的一致性，不作为额外样本计入胜率；不一致不自动判作无效评审。
- 检查共同选择的帖子有哪些内容特征，重点阅读分歧较大的场景，再决定是否修改特征、训练目标或标签定义。
- 这些题专门挑选算法分歧，内容是既有模拟帖子，部分已参与离线训练。即使人工标签是新收集的，也不能称为未见内容上的泛化评估、全量信息流胜率或 NDCG。
- 一旦用这批答案调整模型，它们就是开发证据，不能反复调参后又当成独立测试集。需要另留未见人工样本及后续成熟真实互动复验。
- 本工具没有模型激活接口，汇总明确记录 `diagnosticOnly: true`、`activationAllowed: false`。不会修改正式排序。

## 同时积累真实互动

已上线链路会继续记录登录用户的曝光、阅读和互动。团队正常使用“发现”，按实际喜好收藏、点赞、关注、评论、采用路线和反馈行程满意度即可。不要求密集点击或批量刷行为，也不把人工盲评答案写入正式用户画像。

训练器按曝光后完整 7 天观察窗口生成标签，要求至少 300 条合格样本，并校验按时间隔离的训练、验证、测试集合。达到 7 天不代表所有人数、帖子数、时间隔离和样本门槛都会同时满足。

真实用户阅读模拟帖子的行为目前单独带有内容来源标记，不属于当前纯真实训练集；保留这些真实行为，但不能去掉标记冒充真实内容互动。应逐步有真实用户发布自己的真实路线和帖子，再积累自然反馈。以后如纳入真实用户与模拟内容的混合样本，需单独设计和验证评估范围。

2026-10-18 发布验收时成熟真实样本为 0；该数字是当时快照。达到门槛后仍需验证集和测试集稳定超过规则基线，才能激活双塔。
