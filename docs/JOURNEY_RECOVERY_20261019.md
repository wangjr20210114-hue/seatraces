# 问卷与地点选择中断恢复

日期：2026-10-19，北京时间。

## 本轮保证的范围

在同一站点、同一设备和浏览器配置目录中，为已登录账号保存正在填写的个性化旅行问卷。每次填写或点选立即写本机持久存储，不依赖“下一页”、定时器或页面关闭事件。各账号使用独立键，登录确认前不打开草稿。

| 大模块 | 子模块 | 恢复行为 |
| --- | --- | --- |
| 基本信息 | 出发地、已选城市、起止日期 | 输入后即保存；重新打开继续原页面 |
| 地点选择 | 已选片区 | 保存城市与聚类ID；恢复时优先读服务器原会话快照，不能重新聚类后默默丢掉选择 |
| 地点选择 | 想去/取消想去 | 先记录本机期望值再发请求；离线保留心形，联网后顺序同步；重复点击以最后一次为准 |
| 个性化问答 | 当前题目、已选答案、确认过的条件 | 还没有点击下一题也能恢复；动态问题继续走原 questions 接口 |
| 创建问卷 | 已成功但响应丢失 | 本机先保存clientSessionId；同一输入重试复用原会话，不重复创建 |
| 生成行程 | 已生成但响应丢失 | 读取本人会话的tripId，恢复原行程；不会因重开而自动重复生成 |
| 暂时故障 | 断网、503、启动时无法确认身份 | 保留草稿；启动页重新连接或恢复联网后重试，不把暂时不可达当作草稿不存在 |
| 权限与异常 | 换账号、存储失败、服务器会话不存在 | 不跨账号恢复；存储失败明确提示；会话恢复失败保留本机资料，不静默清空 |

本轮没有建立“所有页面都能离线使用”的保证：自建CityWalk未保存的选点、未成功保存的发帖文字、问AI尚未发送的输入仍需分别接入持久草稿；服务器已保存的行程、帖子草稿和对话继续使用各自的数据库记录。地图、搜索新地点和最终规划依赖联网。

网页没有新增离线应用壳。如果断网后首次打开或冷启动无法取得网页，需要网络恢复后重新打开；本机已存进度仍在。浏览器清除站点数据、无痕窗口关闭、设备存储损坏、操作系统尚未真正落盘等情况无法承诺不丢失。不同设备、浏览器配置目录、开发/正式域名之间不共享本机草稿。

## 数据与接口

本机键：`seatraces-journey-draft:v1:<userId>`，格式`journey-draft/1`，最多256KiB。只保存操作进度、选择ID、少量城市与问题元数据；不存登录凭据、地点全库、原始供应商资料、地图几何或整份行程。内容写不下时保留旧快照并显示保存失败，不把失败显示成成功。

服务器复用PostgreSQL既有journey_sessions、user_place_wishes和trips；没有新增表、索引或迁移。新增GET会话恢复接口、可选clientSessionId和resume=1，旧请求保持兼容，详见[API_REFERENCE](../API_REFERENCE.md)。同一“想去”目标值的并发重试只产生一次兴趣变更信号，目标写入与信号共用事务。

## 手动用例

| 编号 | 小模块 | 操作步骤 | 预期 |
| --- | --- | --- | --- |
| REC-M01 | 基本信息 | 填出发地但不点下一页；关闭浏览器，重新打开同一站点并登录 | 回到输入页，原出发地仍在 |
| REC-M02 | 片区 | 选好城市与日期，点选两个片区；刷新页面 | 返回该城市片区页，两项保持选中 |
| REC-M03 | 想去 | 展开地点，断开网络，点“想去”；恢复网络并重开 | 选择保留并同步，待同步提示结束 |
| REC-M04 | 最终意愿 | 慢网下连续点同一心形，最后停在想去或取消状态；恢复后刷新 | 地图、卡片与服务器最终状态一致 |
| REC-M05 | 问答 | 选择“带父母”，不点下一页，刷新 | 该题与选项保持；后续仍按本次条件提问 |
| REC-M06 | 启动断网 | 已有草稿时让身份查询不可达；再恢复网络 | 不要求重新填写，联网后恢复进度 |
| REC-M07 | 创建响应丢失 | 让创建问卷请求已到服务端但前端收不到响应；刷新重试 | 同一个会话ID，不产生第二份 |
| REC-M08 | 生成响应丢失 | 已生成后中断响应，重新打开 | 恢复已生成行程，完成草稿被清理 |
| REC-M09 | 账号隔离 | A填写一半，切换到B | B不能看到或提交A的问卷；A重新登录可继续 |
| REC-M10 | 存储异常 | 禁止本机持久存储后填写 | 明确显示“本机保存失败，请勿关闭页面” |

## 自动化验收

入口：`e2e/specs/questionnaire-recovery.spec.mjs`，同时运行既有`recovery.spec.mjs`与`weather.spec.mjs`。使用本机隔离PostgreSQL、真实应用与替身供应商；不占用模拟器5555，不在正式用户数据上做压力操作。

`test/journey-recovery.test.mjs`包含即时持久化、账号隔离、损坏/超限存储、35MiB地点库排除、父子地点意愿、5,000次同步快照写入、20并发意愿重试和事务回滚。`test/journey-api.test.mjs`验证六次并发创建、重复标识冲突和恢复归属。两文件纳入自动化UI启动的必跑原生回归。

浏览器配置目录关闭再重启与输入后即时快照测试共同验证软件恢复路径；没有把关闭浏览器的测试称作真实断电实验，也未拔电验证硬件写盘保证。

2026-10-19本机验收结果：18种不同网页用例分批全部通过（9种新增问卷恢复、6种既有恢复、3种天气恢复）；最后一批60个原生文件共376项通过、0失败、0跳过。覆盖20个相同意愿请求并发只产生一次信号、6次并发创建只创建一份问卷、日期input未失焦立即保存、参考帖子不覆盖已取消的意愿，以及地图边界供应商不可达时的候选恢复。

5,000次小型快照序列化与Storage内存替身写入约75毫秒；这不是浏览器落盘速度或硬件断电保证。独立UI测试后端与测试框架进程采样峰值RSS约103MiB、堆约33MiB，排除了浏览器、PostgreSQL和原生子测试进程，且使用小型模拟目录，不能据此推断完整线上容量。已检查恢复界面截图`reports/ui/questionnaire-recovery.png`。
